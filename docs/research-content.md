原站的名录、招式与属性表适合做入门索引，但单靠这些页面不足以说明伙伴战斗数值、招式池、抽卡保底、升级成本和近期机制变化。独立站的覆盖较广，部分规则描述却互相冲突。因此使用“搜索发现问题 → 官方专题交叉核对 → 固定源码版本验证 → 明确区分事实与策略”的流程补充内容。

## 重要纠正

1. **成就不是 127。** 通用指南尚未更新；专题页和固定构建有 130。增加的三项与 October 13 的 Judgment 有关，站内已统一为 130，并记录旧来源差异。
2. **保底是计数先加一再判定。** 当前计数 69 时下一抽强制 5★；不是失败 70 次后第 71 抽。每个地区独立计数，任意 5★ 清零。
3. **十连与十个单抽不同。** 前九次没有 4★/5★ 时，末次在这两个稀有度间重新按 6.5:1.5 归一化；保底先于这一条判定。
4. **重复闪光不能简单写成每次三倍返币。** 当前实现先尝试换成本池同稀有度的未拥有闪光；池已齐则变成普通结果。源码虽然保留三倍返币分支，但不能将它描述为池齐后的常规结果。
5. **Psyduck 是开局招式例外。** 它是 Water 属性，却以 Confusion 开局。可获得招式集合需包含初始招式；升级卡池仍单独按 Normal＋自身属性计算。
6. **招式内部 ID 不等于英文名称。** `leaf-storm` 在该构建显示为 Petal Blizzard；`giga-drain` 显示为 Grass Knot。保留显示名 URL，配装兼容性使用源码 ID。
7. **分钟 60 的旧 overtime 建议已过时。** October 13 引入分钟 30 的 Judgment，Arceus 不可击败，新 Rift 从分钟 28 起停止开启。

## 工具边界

抽卡工具对固定概率、区域池、保底与十连规则进行精确概率递推。“任意 5★”不受同稀有度闪光换物种影响；特定物种目标假设池内等概率，未建模玩家已拥有闪光集合导致的物种重定向。十连输入必须为十的整数倍，单次计划上限 1000 抽。

配装工具验证的是可获得招式集合和独立槽位，不模拟 Bond 分组、随机发牌顺序或全部运行状态。推荐配装不是实测 DPS 榜。天气计算器使用天气峰值；游戏有三秒淡入淡出，另有伙伴/道具等系数。

## 数据维护

- `scripts/data/source-revision.json` 是人工选择的版本与审核日期。
- `npm run data:refresh` 获取该固定版本的专题 HTML 和字面量源码数据，统一导入，失败时恢复先前 JSON。
- `import-pinned-game.mjs` 使用 TypeScript 语法树读取字面量，不用 eval/vm 执行下载的游戏代码。
- 人工文章：`src/data/guides/guides.json`、`src/data/builds/builds.json`；更新摘要：`src/data/wiki/change-summaries.json`。
- 生成结果包括原有图鉴/招式 JSON 和 `src/data/wiki` 下的数值集合。不要手改生成值。
- 变更版本时必须核对名称映射、计数、保底边界、初始例外、招式数值和人工攻略。不能只换 SHA 就声称人工说明已同步验证。
